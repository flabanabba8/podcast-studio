---
name: create-podcast
description: Develop a source-backed podcast script, review it, and prepare an audio production plan.
---

Create a listener-first podcast for the user's actual subject, audience, format, and chosen voices. Do not assume Breach Protocol's characters belong in someone else's show.

1. Research each story from primary sources; read full papers when making claims about them, not just abstracts. Separate confirmed facts, interpretation, disputes, and unknowns. Track source references for every segment.
2. Begin by explaining the subject and what happened. Give necessary context and causal sequence before interpretation. Explain technical terms; avoid filler, invented banter, unsupported claims, and padding. Multiple hosts should respond substantively with complete thoughts.
3. Assemble ordered segments with `title`, `sources` (references), and `turns` (objects with `speaker` and `text`). Run `podcast_check_script` to record exact segment fingerprints. Counts and source references do not validate factual claims.
4. Compare all specific claims against original sources, then review the complete script for clarity, source fidelity, opening, and substantive edits. Build a review object with `reviewer` and ordered `segments`; each segment has its matching `sha256` and notes `purpose`, `opening_check`, `source_check`, and `edits`. Run `podcast_check_review` after the final edit. A match is self-attested, not independent proof. Redo review for changed text.
5. Use an available and explicitly selected speech engine and authorized voices only. If using Higgs, account for its hardware cost and use supported delivery tags; keep tags out of listener-facing captions. Preserve any required model attribution and the credit file produced by PageCast. If PageCast Director is installed, `podcast_pagecast_plan` prepares the reviewed dialogue and a paragraph-to-speaker map. Import its text, inspect the resulting passages, and assign every passage ID in each paragraph to the listed speaker; PageCast can split turns and does not infer speaker identity. Then set approved voices, render bounded batches and export audio. If a PageCast passage is edited, update the structured script and repeat its source/editorial review and handoff; the earlier review hash does not cover edits made inside PageCast. Check generated audio against script, retry only failed portions, then mix and check loudness and timing. Do not claim audio was generated or verified when no engine ran.
6. For a PageCast WAV export, `pagecast_timeline` reports boundaries from verified cached passage audio; use the handoff's segment indices and the earliest passage for each segment to derive chapter starts. Encoding or later edits may change timing, so check the final audio. With explicit `include_text`, PageCast can return sensitive passage text; `podcast_caption_cues` makes passage-timed draft cues and can strip Higgs delivery tags. Follow timeline pages until `next_offset` is empty before claiming full coverage. This is script text, not verified speech or word-level alignment. Prepare descriptive show notes, source links and chapters from measured audio times. `podcast_show_notes` formats one caller-supplied start for each segment and lists source references; verify times and sources independently. Keep outputs private until the user authorizes distribution; do not publish or upload automatically.
